# vfcheck — 录像篡改取证检测工具

不依赖原始录像做对照, 仅从**单份文件本身**的编码结构、时间戳、画面噪声和场景连续性
检测删帧、插帧、拼接和画面局部替换, 标出可疑时间段并给出依据。

## 构建

```bash
cd detector
cmake -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build
```

依赖: FFmpeg 开发库 (libavformat/libavcodec/libavutil/libswscale), CMake, C++17。
macOS: `brew install ffmpeg cmake`。

## 使用

```bash
vfcheck <录像文件> [--json 报告.json] [--verbose]
```

退出码: 0 = 未发现可疑, 1 = 发现可疑时间段, 2 = 错误。

## 检测原理 (五层证据, 单遍扫描)

| 层 | 依据 | 针对的篡改 |
|---|---|---|
| 时间戳 | DTS 间隔缺口/不单调 (不解码) | 删帧、插帧的容器级痕迹 |
| 编码结构 | GOP 长度异常、P 帧码率水平突变 (不解码) | 剪切点重编码、异源拼接 |
| 噪声 | 逐帧传感器噪声 σ (Laplacian 截尾均值), 滚动中值 + MAD 离群、水平漂移 | 异源片段、二次压缩 |
| 连续性 | 模糊图帧间差分: 突增 = 删帧/切口; 持续≈0 = 重复/冻结帧 | 删帧、插帧、拼接 |
| 局部区域 | 8×6 分块噪声网格, 每块与自身全片时域基线比较, 紧凑异常簇持续出现 | 画面局部覆盖/替换 |

**证据融合**: 各检测器产出带分数 (0–1) 的事件, 时间上重叠或间隔 <2.5s 的事件归并为一组,
组内分数按 noisy-or 合成 `1 − Π(1 − sᵢ)`, 输出置信度 (高 ≥0.85 / 中 ≥0.6 / 低) 和每条依据。

关键设计:
- **帧差在 3×3 模糊后的缩略图上计算** —— 压制逐像素传感器噪声, 让删帧造成的内容跳变凸显;
  同时要求相对局部基线突增 + 全局 MAD 离群, 排除画面自身周期性运动的干扰。
- **噪声估计用 Laplacian 响应的截尾均值** (去掉 15% 最大响应) —— 对画面边缘稳健, 反映传感器噪声底。
- **区域检测用每格的全片时域中位数作基线** —— 固定机位下, 长时段篡改也无法把基线带偏;
  排除绝对水平过低的纯平坦块 (避免把正常运动物体误判为覆盖块)。

## 性能

单遍扫描, 解码后缩放到 192×108 灰度图做分析, 多线程解码。
实测 (Apple Silicon): **1 小时 360p 录像约 24 秒跑完 (~150 倍实时, ~3800 帧/秒)**。

## 测试

```bash
testdata/make_videos.sh   # 合成原始监控录像 + 6 种篡改版本 + 1 小时性能文件
python3 testdata/eval.py  # 对照 ground truth 自动评估
```

合成场景: 静态背景 + 匀速运动物体 + 时域传感器噪声 (σ≈20), 固定 GOP=50, 无 B 帧, crf 21。
篡改版本: 删帧 (流拷贝/重编码两版)、插入异源片段、后半段拼接、局部区域覆盖 (移动块)、
重复冻结帧; 对照组: 原始文件、仅整体重编码。

**评估结果: 6/6 篡改全部检出, 2 个对照组 0 误报。**

## 局限

- 篡改者若用相同设备、相同参数重编码整段, 且内容本身连续 (如仅删掉静止画面时段),
  留下的痕迹很弱, 可能漏检 —— 单文件取证的理论极限。
- 画面剧烈变化的非监控 footage (电影剪辑、运动相机) 会在连续性层产生误报, 本工具面向
  固定机位监控录像调优。
- 噪声层依赖编码后残留的传感器噪声; 极低码率 (噪声被压没) 的录像该层失效,
  其余各层仍工作。
